# RateGate

[English](README.md) | [Русский](README.ru.md)

RateGate — HTTP-шлюз для проксирования запросов и ограничения их частоты по ключу клиента.

## Возможности

- HTTP-сервер на порту 8080.
- `GET /health` возвращает `200 OK` и `{"status":"ok"}`.
- Таймауты HTTP-сервера.
- Корректная остановка по Ctrl+C или SIGTERM с ожиданием текущих запросов.
- Обратный прокси: пересылка запросов целевому сервису с сохранением метода, пути, параметров и тела.
- Ответ `502 Bad Gateway`, если целевой сервис недоступен.
- Ограничение времени обращения к целевому сервису: `504 Gateway Timeout`, если время истекло до получения заголовков ответа.
- Настраиваемое ограничение запросов для каждого ключа по алгоритму token bucket: по умолчанию 10 запросов в секунду с запасом на 10 запросов.
- Ответ `429 Too Many Requests` с заголовком `Retry-After` при превышении лимита.

## Запуск

Требуется Go 1.22 или новее.

```sh
UPSTREAM_URL=http://localhost:9000 go run ./cmd/rategate
```

Скорость пополнения лимита и максимальный запас запросов задаются при запуске:

```sh
UPSTREAM_URL=http://localhost:9000 RATE_LIMIT=5 RATE_BURST=20 go run ./cmd/rategate
```

`RATE_LIMIT` — количество токенов, добавляемых в секунду. `RATE_BURST` — максимальное количество токенов, которое также сразу доступно новому ключу. Каждый запрос расходует один токен. Если переменные не заданы или пусты, обе настройки равны `10`. Допустимы целые числа от `1` до `1000000`. При неверном значении сервер завершает запуск с ошибкой.

`UPSTREAM_TIMEOUT` задаёт общее время обращения к целевому сервису. Если переменная не задана или пуста, используется `5s`. Допустимы положительные интервалы в формате Go до `1m` включительно, например `500ms` или `10s`. При неверном значении сервер завершает запуск с ошибкой.

```sh
UPSTREAM_URL=http://localhost:9000 UPSTREAM_TIMEOUT=3s go run ./cmd/rategate
```

Таймаут включает отправку запроса и чтение тела ответа. Если время истекло после отправки заголовков клиенту, передача ответа прерывается: заменить его статус на `504` уже невозможно. Отмена запроса клиентом также отменяет обращение к целевому сервису.

При Ctrl+C или SIGTERM RateGate закрывает слушающие сокеты и неактивные соединения, затем ожидает завершения текущих запросов. На остановку отводится `UPSTREAM_TIMEOUT` плюс 5 секунд. Если этого времени не хватило, оставшиеся соединения закрываются, а процесс завершается с ошибкой.

Проверка сервера:

```sh
curl -i http://localhost:8080/health
```

`UPSTREAM_URL` обязателен и должен содержать абсолютный HTTP- или HTTPS-адрес без учётных данных и фрагмента (`#...`). Целевой сервис необходимо запустить отдельно. Если в его адресе указан префикс пути, он добавляется перед путём каждого запроса.

Все запросы, кроме `GET /health` и `HEAD /health`, требуют заголовок `X-API-Key` и проходят проверку лимита перед пересылкой:

```sh
curl -i -H 'X-API-Key: demo-client' 'http://localhost:8080/api/items?page=1'
```

Ключи разделяют лимиты клиентов. Они не проверяются как учётные данные и не обеспечивают аутентификацию. Если ключ отсутствует, пуст или превышает 256 байт, возвращается `400 Bad Request`. Пробельные символы в начале и конце ключа игнорируются. Проверки `/health` обходят ограничение запросов.

Лимиты хранятся в памяти каждого процесса и сбрасываются при перезапуске. Неактивные ключи удаляются при очередной очистке после как минимум одной минуты простоя, когда их запас токенов уже полностью восстановился бы. Несколько экземпляров RateGate не используют общий лимит.
